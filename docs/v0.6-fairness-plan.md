## 1. Why

Measured against a real season (`examples/calendar_dates_times_sr_mens.csv`, 236 slots,
16 teams / 8 per division).

### 1.1 Half the fairness system is inert

Zero Friday or Saturday slots (Sunday 138, Tuesday 48, Wednesday 50). The weekend
variance term, `weekendVarianceFlag`, and report Section D all compute zero. Normal
for this league, not an anomaly — and therefore gated, not left rendering an all-zero,
all-"✓ OK" table (Phase 4).

### 1.2 The optimiser balances only what it is told to measure

Per-time-slot spread (max − min across the 8 teams in a division):

| | 15:15 | 16:30 | 17:45 | 19:00 | 20:15 | 20:45 | 21:00 | 21:30 | 22:00 | 22:15 |
|---|---|---|---|---|---|---|---|---|---|---|
| Div A | 3 | **6** | 2 | 4 | 4 | 1 | 1 | 0 | 1 | 1 |
| Div B | 4 | 3 | 3 | 4 | **5** | 0 | 1 | 1 | 0 | 1 |

Graded (late) slots land at 0–1; ungraded slots drift to 2–6. Aggregated by band the
error compounds on the same teams — one team drew 11 prime games and 3 afternoons
while a divisionmate drew 5 and 9.

### 1.3 Same-day double- and triple-headers are structurally forced

A 6-slot date given wholly to an 8-team division yields 12 team-appearances over
8 teams — by pigeonhole at least 4 teams play twice, before the optimiser chooses
anything. Measured: **92 extra same-day games including 10 triple-headers.**
`maxGamesPerWeek = 3` does not prevent this — three games in one afternoon satisfies it.

## 2. Locked decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Slots assigned in **contiguous per-division blocks**, at most **one block per division per date** | The one-division-per-date rule exists for post-game socialisation; a contiguous run preserves it. One block per division keeps contiguity unconditional. |
| 2 | A date is split only when a whole-date assignment would force same-day games (`2 × slots > division team count`) | Keeps the common case unchanged. |
| 3 | 6-slot Sundays split **4 / 2**, the leading block alternating by chronological index | A 4-block = 8 appearances over 8 teams = every team plays exactly once, whole division present. ~12 full-division nights each per season. |
| 4 | **Every ice slot must be used.** `games.length === iceSlots.length` is a hard invariant | Ice is paid for; an empty slot is wasted. |
| 4b | **Domain guarantee (product owner):** a date never carries more slots than the two divisions can host — `slotsOnDate <= cap(A) + cap(B)` always holds for a properly-configured season | Ice is booked against the league's actual capacity, so overflow is not a real-world case. This makes #4 and #9 unconditionally compatible: every slot places with zero same-day games. Confirmed on the real file — largest date 6, capacity 8. |
| 4a | A division with fewer than 2 teams receives **no slots**; its share goes to the viable division | Closes an existing waste: today an 8-vs-1 roster still allocates ~1/9 of the season to the single-team division, where those slots can never be played. |
| 5 | Slot budget target **118 / 118** | No cross-division play in league or playoffs, so cross-division late/prime gaps have no audience. Slot count is the only cross-division property that matters. |
| 6 | Three time-of-day bands, boundary configurable via `primeWindowStart` | afternoon `< primeWindowStart` · prime `→ lateGameThreshold` · late `≥ lateGameThreshold`. |
| 7 | Balance **per-band totals**, not per-individual-slot | Targets the observed failure; leaves the annealer freedom to keep late rigid. |
| 8 | **Late band stays rigid.** Prime/afternoon best-effort, weighted strictly below | Explicit product instruction. |
| 9 | **No same-day games — an invariant, not a setting** | Product owner: it can never happen. Permanent penalty; structural blocking does the real work. |
| 10 | Feasibility failures are **warnings**, never empty schedules | Review Critical #1. |
| 11 | No change to seed reproducibility | Verified: replaying a stored seed reproduces content exactly. |

### Non-goals

- Cross-division late/prime balancing (decision #5).
- Incremental/delta scoring. *(Rationale corrected per review: it buys wall-clock, not convergence. Revisit only if Phase 5 breaches the 90 s budget.)*
- Best-of-N restarts — re-open only if the new objective measures worse.
- Playoffs, multi-user, mobile (PRD §6).

### Phase 2 — Slot-block assignment + feasibility

The structural change. **Do not start until this section's algorithm is implemented as
written** — review gate.

#### Block partition

```
cap(d)  = floor(teamCount(d) / 2)        // max games a division hosts without doubles
eligible = divisions with teamCount >= 2 // a division with <2 teams never receives a block

for each date (chronological), slots sorted by startTime:
  n = slots.length

  0 eligible divisions -> all n slots unused

  1 eligible division d:
      take the leading min(n, cap(d)) slots as one block; remainder unused

  2 eligible divisions:
      lead  = alternate(A, B) by chronological split-date index
      other = the other division
      if n <= cap(lead):                       -> whole date to whichever division the
                                                  budget greedy prefers, provided
                                                  n <= cap(thatDivision)
      else:
          k = min(cap(lead), n)                // largest legal leading block
          if n - k > cap(other): k = n - cap(other)   // shrink lead so other fits
          block(lead)  = slots[0 .. k)
          block(other) = slots[k .. n)         // every remaining slot is placed
```

**Capacity overflow (`n > cap(A) + cap(B)`) is out of scope as a user flow.** Per domain
guarantee #4b it cannot arise from a properly-configured season, so no manual-assignment
UX is built for it. It remains reachable only through a **misconfigured roster** — 8-vs-1
teams strands division B (decision #4a), leaving `cap = 4` against 6-slot Sundays. That is
a roster problem, not a scheduling problem, and it is caught **before generation** by the
feasibility warning rather than handled mid-run.

Backstop: a tripwire assertion in `dayAssignment.ts`, following the house pattern already
used in `fairness.ts:141` for negative Late Surplus — a condition that cannot occur by
construction and therefore signals a bug rather than a user error.

Properties this guarantees:
- **At most one block per division per date** ⇒ every block is contiguous, unconditionally.
- **No forced same-day games, ever** — surplus is dropped rather than doubled up.
- Degenerate divisions (`cap < 1`) take no block instead of looping.
- Unequal divisions work: with 7 teams `cap = 3`, so a 6-slot date splits 3/3.

**Sit-out fairness.** When a block is smaller than `teamCount/2` some teams sit out that
date. This needs no extra rule: `buildMatchups` already sizes the pool to the division's
slot count and balances per-team game counts to ±1 by construction, so sit-outs even out
across the season.

**Ordering.** Split-required dates are allocated **first** and **chronologically** (the
existing `assignDays` sorts by `slotCount desc`, which is wrong for alternation). Whole
dates are then greedied against the remaining budget.

**Acceptance**

- Zero forced same-day games on the real file (from 92 extra games / 10 triple-headers).

### Phase 5 — Measure and tune

1. **Make cooling adaptive**: `COOLING = (MIN_T/T0)^(1/iterations)`. Today it is a fixed
   0.9997 that floors at ~30,700 regardless of budget, so Phase 5's nominal lever —
   raising the iteration count — is inert. Without this, tuning has nothing to pull.
2. Re-run convergence on the real file; confirm or revise 50,000.
3. Tune band weights empirically. Engineering measured weight 150 leaving afternoon spread
   at 2, and 1500 reaching 0 but degrading prime — so this is a real search, committed as a
   **checked-in script plus asserted constants**, not a manual loop.
4. Perf check against the real file; stated action if the 90 s budget is breached.
5. Regenerate `perf-baseline.json`; update `standards.md` §2.1 and the ADR weights table
   with final measured values.

## 6. Risks

| Risk | Mitigation |
|------|------------|
| Band balancing fights late rigidity | `lateRigidity.test.ts` is the gate; band weights yield, never late |
| A slot goes unplayed | Hard invariant + test. Ruled out by domain guarantee #4b for any properly-configured season; only a misconfigured roster can reach it, and that is caught by the pre-generation feasibility warning |
| Convergence moves once the objective grows | Adaptive cooling first, then re-measure — Phase 5 steps 1–2 |
| Scoring cost grows with two new accumulators against a 90 s budget | Phase 5 step 4 measures on the real file |
| Roster lock confuses | Non-destructive unlock + rename ship in the same phase |
