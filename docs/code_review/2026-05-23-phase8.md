## Findings

### Critical

### Major

### Minor

1. **`coverage/` directory leaked into lint scope.** Vitest v8 coverage
   writes an `lcov-report/` tree of generated JS files into `coverage/`
   in CWD. Neither `.gitignore` nor `eslint.config.js` was excluding it,
   so `npm run lint` after `npm run test:coverage` surfaced three
   "Unused eslint-disable directive" warnings on generated code.
   **Fixed in commit `7030a1e`** by adding `coverage` to both
   `.gitignore` and the ESLint top-level `ignores` array. CI was not
   affected (it runs lint before tests), but local DX was.

2. **`reassignSlot` ignored the new `generateId()` helper.** DAV-65
   introduced `src/lib/generateId.ts` as the canonical UUID v4 source,
   but `useSchedulerStore.reassignSlot` (touched by DAV-66) was still
   building game ids via
   `\`reassign-${Date.now()}-${Math.random().toString(36).slice(2, 9)}\``.
   This is non-UUID-shaped and inconsistent with the helper introduced
   in the same phase. **Fixed in commit `0e87315`** — `reassignSlot`
   now calls `generateId()`.

### Out-of-scope follow-ups (NOT fixed in this review)

The following pre-existing call sites still use ad-hoc id construction
and should migrate to `generateId()` in a follow-up ticket — they are
outside the Phase 8 commit boundary so I did not change them:

- `src/components/TeamsTab.tsx:49,219` — `team-${Date.now()}` and
  `team-${Date.now()}-${i}`
- `src/parsers/csvParser.ts:14` — `slot-csv-${++_idCounter}-${Date.now()}`
- `src/parsers/excelParser.ts:8` — `slot-xlsx-${++_idCounter}-${Date.now()}`
- `src/lib/csvParser.ts:107` (legacy) — `slot-${i}-${Date.now()}`
- `src/scheduler/homeAway.ts:16` — `ts = Date.now()` used in id construction

The deterministic ids in the scheduler / parsers are deliberate
(reproducibility under a seeded RNG), so the migration there is a
design call, not a defect.

## File-level review notes

### `src/lib/generateId.ts` (DAV-65)

- JSDoc complete, explains both the secure-context-only `randomUUID()`
  path and the `getRandomValues` fallback (Vite LAN-served dev). Good.
- Throws an `Error` with a clear message when neither API is available
  — explicit failure rather than silent fallback to a weaker source.
- Bit-twiddling for the v4 / variant nibbles is correct
  (`(byte[6] & 0x0f) | 0x40`, `(byte[8] & 0x3f) | 0x80`).
- Tests cover happy path, 1000× uniqueness, fallback path with
  `randomUUID` stubbed, and the throw path with `crypto` stubbed.

### `src/lib/debouncedStorage.ts` (DAV-66)

- Module-level `Map` is correct here — debounced storage is genuinely a
  process-global concern, and the module is the natural scope. No
  hidden globals leak across tests because `cancelPending()` clears the
  map and the tests call it in `afterEach`.
- Custom delay parameter is plumbed through and tested.
- Catches every `localStorage` access — defends against quota and
  non-browser environments. Good.
- JSDoc on each public export. Good.

### `vitest.config.ts` (DAV-64)

- Per-path thresholds correctly scoped (`src/scheduler/**/*.ts`,
  `src/parsers/**/*.ts`). Comment block explains why the store
  threshold is parked.
- Worker exclusion (`src/scheduler/worker.ts`) is justified inline.
- Coverage `include` is scoped to `src/**`; `exclude` properly skips
  components, pages, root entry files, tests, fixtures, and `.d.ts`.

### `src/hooks/useSchedulerStore.ts` (DAV-66)

- `scheduleWrite` wired correctly per persisted slice; schedule slice
  passes `null` when the schedule is cleared (so the debounced layer
  issues `removeItem`).
- `beforeunload` flush registered and cleaned up in a `useEffect`. Good.
- `clearAll` now calls `cancelPending()` before issuing the synchronous
  removes — required so a queued write doesn't resurrect a key after
  reset.
- JSDoc on each callback. Naming and file length (≤252 lines) within
  standards.

### TeamsTab (DAV-68 verification)

- `TeamsTab.tsx:84` uses `onKeyDown={handleKeyDown}`. No `onKeyPress`
  remains anywhere under `src/`. Verified via `grep -rn`.
