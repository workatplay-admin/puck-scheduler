## Issues Found and Fixed

### [FIXED] Logic: `toggleSection` prematurely dismissed the Updated badge

**File**: `src/components/FairnessReport.tsx`, line 22 (before fix)
**Severity**: Minor — user experience regression

`toggleSection` called `onDismissUpdated?.()` on every collapsible toggle, meaning the "Updated" badge was cleared whenever the user expanded or collapsed *any* section of the Fairness Report, including sections unrelated to reviewing the change. The badge should only be dismissed via the explicit badge button click.

**Fix**: Removed `onDismissUpdated?.()` from `toggleSection`. The badge remains dismissible via the dedicated button on the card header (line 45).

---

**File**: `src/types/scheduler.ts`

## Architecture / Design Observations

- **Store shape is correct**: `fairnessReport` and `fairnessReportUpdated` belong in `SchedulerState`; they are derived data that must survive tab navigation.
- **Auto-recalc pattern**: Recalculating inside every mutating callback (`swapGames`, `removeGame`, `reassignSlot`, `setSchedule`) is the right approach — keeps the report always in sync without needing external observers. The `recalculateFairnessReport` escape hatch for manual override is also well-placed.
- **UnusedSlotsSection**: Good separation of concerns. The `inferSlotDivision` heuristic (same-date games) and `pickHomeAway` (fewest home games, deterministic tiebreak) are sound for a manual reassignment UX.
- **ID generation** (`reassign-${Date.now()}-${random}`): Acceptable for a client-side single-session store; no collision risk in practice.
- **ScheduleTab.tsx at 491 lines**: One line under the 500-line limit. If further features are added to this file it will need splitting — likely by extracting the schedule table into `ScheduleTable.tsx`.
- **FairnessReport.tsx at 473 lines**: Same note — a collapsible section extraction would be prudent before the next feature lands here.
